### Порядок работ этапа 3 (итерации по 1–2 недели)
1. ✅ Каркас: вход, роли и права из интерфейса, филиалы, журнал действий.
2. ✅ Лиды: воронка (канбан), карточка, лента, задачи, проверка дублей, отказ с причиной.
3. ✅ Студенты: карточка, фильтры, перевод лида в студента.
4. ✅ Курсы, группы, лист ожидания; расписание с шаблонами и контролем конфликтов.
   Перенесено в другие итерации: перерасчёт остатка при переводе — в 6 (финансы); push о переносе и замене — в 8;
   ссылка Zoom/Meet — в 10; учебный план уровня и отметка пройденной темы — в 5; самозапись в свободные слоты (Ж) — после MVP.
5. ✅ Посещаемость, списание занятий, оценки по навыкам, правило «2 пропуска подряд»; учебный план курса и тема урока.
   Списание фиксируется в отметке (`Attendance.charged`); уменьшение остатка абонемента — в итерации 6.
   Уведомления родителям ставятся в очередь (`Notification`), отправка по каналам — в итерации 8.
   Офлайн-отметки: API принимает `clientTime` (побеждает более поздняя отметка); локальное хранение — в мобильном приложении (этап 4).
6. ✅ Финансы: прайс, абонементы, оплаты, задолженность, расчёт оплаты преподавателей.
   Оплата преподавателей (решение заказчика от 21.11.2026): за каждого пришедшего студента — процент от цены
   занятия по его абонементу: новый преподаватель — 30 %, опытный — 50 %; за пропуски студента (без причины
   и по уважительной) оплата не начисляется. Ставки и категории меняются в интерфейсе.
   Перенесено: автоматический счёт и напоминания о долге — в итерацию 8 (уведомления); промокоды как справочник,
   расходы филиала (Ж) — после MVP; онлайн-эквайринг и QR — в итерацию 10.
7. ✅ ДЗ и тесты, входной тест уровня по ссылке.
   Правила по умолчанию (можно изменить по решению заказчика): ДЗ-тест — одна попытка; уровень во входном
   тесте засчитывается при ≥ 60 % по вопросам уровня (последовательно A1 → C1); после теста лид переходит
   на этап, следующий за «Тест уровня». Файлы — до 20 МБ (фото, PDF, Word, аудио), хранятся на сервере
   в `apps/api/uploads` (для продакшена — объектное хранилище S3, этап развёртывания).
   Перенесено: уведомления «новое ДЗ» и «оценка» — итерация 8; офлайн-сдача — мобильное приложение (этап 4);
   защита публичного теста от спама (капча, лимиты запросов) — при развёртывании.
8. ✅ Уведомления и шаблоны (push, WhatsApp, Telegram, SMS, e-mail), внутренний чат.
   Каналы подключаются ключами провайдеров в `.env` (см. `apps/api/.env.example`); до этого — режим имитации
   (сообщения в журнале со статусом «Имитация»). Push сейчас — уведомление в веб-кабинете; FCM — этап 4.
   WhatsApp Business: вне 24-часового окна Meta требует одобренные шаблоны — регистрирует заказчик.
   Чат — опрос раз в 5 с; WebSocket — при необходимости на этапе 4. Перенесено: опросы NPS (Ж) — после MVP.
9. ✅ Документы PDF, отчёты и дашборд директора, выгрузка Excel/PDF.
   Документы: договор, счёт, акт (по абонементу), справка, сертификат; сквозная нумерация и реестр.
   Реквизиты центра хранятся в базе и редактируются на странице «Реквизиты центра» (в репозиторий не попадают).
   Текст договора — шаблон по умолчанию: согласовать с юристом заказчика. Не указаны ИНН и ОКПО — заполнить в реквизитах.
   Отчёты: воронка, выручка (план/факт), задолженность, загрузка, удержание, посещаемость и успеваемость
   (с внешними экзаменами), зарплатная ведомость; Excel — выгрузка, PDF — печать из браузера.
   Перенесено (Ж): подписание договора по SMS-коду, QR-проверка сертификата — после MVP.
10. ✅ Интеграции MVP: webhook сайта, WhatsApp, Telegram, SMS, эквайринг/QR, ЭКМ, Zoom/Meet, FCM.
   Работает без ключей: приём заявок с сайта, исходящие webhook-и (подпись HMAC, повторы), онлайн-уроки
   через Jitsi Meet, оплата по ссылке (тестовый режим), очередь фискальных чеков (имитация).
   Подключается ключами в `.env` после выбора провайдеров заказчиком (ТЗ 5): WhatsApp Cloud API, Telegram-бот,
   SMS-шлюз, e-mail, Zoom, эквайринг/QR банка (универсальный адаптер), онлайн-касса ЭКМ.
   FCM (push в мобильное приложение) — вместе с приложением, этап 4.
   Дополнительно (по образцам заказчика): договоры по шаблонам — консультационные услуги (с актом)
   и FerienJob (с приложениями). Тексты шаблонов и реквизиты хранятся только в базе; поля подстановки {{…}},
   сквозная нумерация с продолжением бумажных номеров, акт к договору одной кнопкой; паспорт и адреса
   в карточке клиента (видны только ролям с правом на контакты).
   Для продакшена: PAYMENTS_TEST_MODE=0, WEBHOOK_ALLOW_PRIVATE=0, PUBLIC_WEB_URL/PUBLIC_API_URL — адреса сервера.

### Порядок работ этапа 4 (мобильное приложение, `apps/mobile`, Expo SDK 52)
1. ✅ Каркас и клиентские сценарии: вход, переключение ролей, языки (рус/кыр), время центра; студент и родитель —
   баланс и оплата долга по ссылке, абонементы с остатком занятий, расписание с входом в онлайн-урок, оценки и
   посещаемость, ДЗ (ответ текстом), сообщения; преподаватель — занятия на день/неделю и журнал в 2 нажатия
   с офлайн-очередью (S9); push через Expo Push Service (FCM / APNs), регистрация телефона на сервере;
   кэш данных для просмотра без связи. API: `/me/devices`, `/me/cabinet`, `/me/students/:id/pay`.
2. ✅ ДЗ с телефона: фото тетради (камера / галерея), файл, голосовой ответ до 5 минут с автостопом; файлы
   задания — фото показываются, аудио проигрывается; оценка и комментарий преподавателя; пересдача после
   возврата. ДЗ-тесты в приложении: выбор, артикль, сопоставление, вписать слово, аудирование; таймер
   с автосдачей, ответы сохраняются на телефоне до отправки.
3. ✅ Чат в приложении: чат группы, личный «студент — преподаватель», обращение в администрацию филиала;
   фото, файлы и голосовые; новые сообщения подгружаются, пока чат открыт; push о новых сообщениях,
   нажатие на push открывает переписку; счётчик непрочитанных на вкладке. Ушедший из группы
   (перевод, окончание) перестаёт видеть её чат. У студента «Успехи» открываются с главной (6 вкладок).
4. ✅ Преподаватель с телефона: оценки по навыкам (Hören, Lesen, Schreiben, Sprechen, итог) по шкале центра,
   тема урока из учебного плана (в том числе в офлайн-отметке), перенос и отмена занятия. Расписание меняет
   роль с правом `schedule.update`; преподаватель без него отправляет запрос — администраторам филиала
   создаётся задача в CRM и приходит push (API: `POST /lessons/:id/change-request`).
5. Сборки EAS (Android / iOS), ключи FCM и APNs, иконка и экран загрузки по дизайну (этап 2), публикация — этап 6.

### Подготовка пилота (этап 5)
1. ✅ Перенос данных: студенты и лиды из Excel (.xlsx) или CSV (Google Таблицы, другая CRM) — раздел «Перенос данных».
   Автосопоставление колонок по заголовкам, проверка без записи, отчёт о пропусках; дубли по телефону и e-mail
   (в базе и внутри файла); телефоны КР приводятся к 996…; родитель — учётная запись по телефону со связью с ребёнком;
   начальный остаток — проводка «opening», в выручку не входит. Группы и абонементы при переносе не создаются —
   зачисление в группы делается в CRM после переноса (нужен формат исходных данных заказчика, вопрос 3.3).

## 3.2. Сценарии приёмки (черновик)

| № | Сценарий | Роли |
|---|---|---|
| S1 | Заявка с сайта (webhook с UTM) → лид в «Новая заявка» → назначен менеджер → задача «первое касание за 15 мин» | система, менеджер |
| S2 | Менеджер звонит → «Контакт установлен» → отправляет тест уровня → результат в карточке → «Тест уровня» | менеджер, лид |
| S3 | Запись на пробный урок → «Пробный урок» → договор → оплата в приложении → «Зачислен в группу» | менеджер, студент |
| S4 | Отказ: перевод в «Отказ» без причины невозможен; с причиной — попадает в отчёт причин отказов | менеджер |
| S5 | Повторная заявка с тем же телефоном → система предлагает объединение карточек | менеджер |
| S6 | Администратор создаёт роль «Методист» с правами только на чтение студентов и групп — без программиста | директор |
| S7 | Пользователь с ролями «администратор» и «преподаватель» переключается между ними без повторного входа | администратор |
| S8 | Менеджер филиала А не видит лиды и студентов филиала Б (проверка через API) | менеджер |
| S9 | Преподаватель отмечает посещаемость с телефона в 2 нажатия без интернета; после появления связи данные на сервере | преподаватель |
| S10 | Удаление оплаты без причины невозможно; с причиной — запись в журнале действий | бухгалтер |

Каждый сценарий проверяется в вебе, на Android и iOS.
