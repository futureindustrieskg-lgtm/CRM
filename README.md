# CRM учебного центра немецкого языка

Единая CRM: веб-кабинет для сотрудников и мобильное приложение (Android/iOS) на одном REST API.
Техническое задание — файл `ТЗ CRM для учебного центра немецкого языка (веб + Android iOS).docx`.

| Часть | Технологии | Папка |
|---|---|---|
| Сервер / API | Node.js, NestJS, Prisma, PostgreSQL | [apps/api](apps/api) |
| Веб-кабинет | React, Vite, TanStack Query | [apps/web](apps/web) |
| Мобильное приложение | React Native (этап 4) | `apps/mobile` — будет добавлено |

## Что уже работает (каркас этапа 3)
- Вход по e-mail/телефону и паролю, JWT + обновление сессии.
- Роли и права по модулям (чтение/создание/изменение/удаление/экспорт), редактирование из интерфейса.
- Несколько ролей у одного сотрудника, переключение без повторного входа.
- Ограничение данных по филиалу на уровне API; менеджер видит только свои лиды.
- Журнал действий (до/после, причина).
- Лиды: воронка канбан/список с перетаскиванием, карточка, история, задачи, контроль первого касания (15 мин),
  проверка дублей и объединение, отказ только с причиной, UTM-метки, перевод в студенты.
- Приём заявок с сайта: `POST /api/v1/webhooks/site-lead` (заголовок `X-Webhook-Token`).
- Студенты: список с фильтрами (статус, уровень, филиал, должники), карточка, согласие на ПД.
- Дашборд: воронка, лиды, конверсия, студенты, должники, выручка.
- Курсы (уровень, формат, часы, учебник, цена) и кабинеты филиалов.
- Группы: преподаватель, кабинет, минимум/максимум, даты, статус; зачисление, лист ожидания с автоматическим
  переводом в основной состав, перевод в другую группу с причиной, массовый перевод на следующий уровень;
  задача администратору филиала при наборе минимума.
- Расписание: календарь на день/неделю/месяц с фильтрами по филиалу, кабинету, преподавателю и группе;
  создание занятий по шаблону (например, пн/ср/пт 19:00–20:30) на весь курс с пропуском праздников;
  контроль конфликтов (преподаватель, кабинет, студент); перенос, замена преподавателя и отмена — с причиной в журнале.
  Время — по часовому поясу филиала. Преподаватель видит только свои группы и занятия.
- Посещаемость: экран «Занятия на сегодня», отметка в два нажатия (был / опоздал / уважительная / без причины),
  тема урока из учебного плана курса; списание занятия по правилам центра; журнал группы с процентом посещаемости.
- Оценки по навыкам Hören / Lesen / Schreiben / Sprechen; шкала центра — проценты, баллы или 1–6;
  успеваемость в карточке студента.
- Правило «N пропусков подряд»: задача менеджеру (или администратору филиала) и уведомление родителю в очереди.
- Правила обучения центра (списание, порог пропусков, шкала) настраивает владелец.
- Финансы: прайс-лист (месяц, уровень, пакет, рассрочка), продажа абонементов со скидками (семейная, за друга,
  за уровень, промокод), приём оплат и возвратов, удаление записей только с правом и причиной.
  Баланс студента = оплаты − стоимость абонементов; отмеченные занятия списываются с абонементов по очереди,
  занятия без абонемента учитываются как долг. Перевод в другую группу переносит остаток денег в новый абонемент;
  расторжение пересчитывает цену по использованным занятиям. Должники, заканчивающиеся абонементы, сводка за месяц.
- Оплата преподавателей: за каждого пришедшего студента — 30 % (новый) или 50 % (опытный) от цены занятия
  по абонементу студента, за пропуски — 0. Ведомость с расшифровкой по занятиям; преподаватель видит свой расчёт.
- Интерфейс на русском и кыргызском (частично немецкий и английский), адаптивная вёрстка от 360 px.

- Домашние задания: группе или одному студенту, текст, файлы, ссылки, срок, навык; сдача студентом
  (текст, фото, файлы, запись голоса до 5 минут), проверка с оценкой, комментарием и голосовым ответом,
  возврат на доработку; оценка за ДЗ идёт в успеваемость по навыку.
- Тесты: конструктор (выбор ответа, артикль der/die/das, сопоставление, вписать слово, аудирование с файлом),
  автопроверка, ограничение по времени; ДЗ-тест с оценкой в шкале центра.
- Входной тест уровня: личная ссылка для лида из карточки или общая ссылка для сайта (`/test/<код>`);
  результат — уровень в карточке лида, запись в истории и переход сделки на следующий этап.
- Кабинет студента: «Мои задания», сдача и тесты.
- Уведомления: колокольчик в кабинете; автоматические сообщения — напоминание о занятии за 2 часа, новое ДЗ,
  проверка ДЗ, оценки, перенос/отмена занятия, оплата, долг (раз в неделю), заканчивается абонемент,
  день рождения, пропуски подряд (родителям). Шаблоны на русском и кыргызском с полями {{name}}, {{amount}}…;
  порядок каналов для каждого типа (push, Telegram, WhatsApp, SMS, e-mail); журнал отправки; рассылки
  по сегментам (уровень, статус, группа, «завершили уровень», должники, лиды). Ключи провайдеров — в `.env`.
- Чат: группы, «студент — преподаватель», «клиент — администрация филиала»; файлы и голосовые.
- Документы PDF: договор, счёт (с суммой прописью), акт, справка об обучении, сертификат об окончании уровня;
  сквозная нумерация (Д-2026-0001…) и реестр. Реквизиты центра вводятся в интерфейсе («Реквизиты центра»).
- Договоры по шаблонам («Документы» → «Шаблоны договоров»): текст с полями подстановки
  ({{client.name}}, {{client.passport}}, {{price}}, {{priceText}}, {{company.inn}}…), необязательный текст акта,
  цена по умолчанию; нумерация общая и может продолжать бумажную (например, с 872). Договор и акт выдаются
  из карточки клиента. Тексты шаблонов хранятся только в базе — в репозиторий не попадают.
- Внешние экзамены студента: Goethe, telc, ÖSD, TestDaF — регистрация и результат.
- Отчёты с фильтром по периоду и филиалу и выгрузкой в Excel: воронка, выручка (план/факт), задолженность,
  загрузка групп, кабинетов и преподавателей, удержание и LTV, посещаемость и успеваемость, зарплатная ведомость.
  Ключевые показатели — на дашборде директора.

- Интеграции (раздел «Интеграции»): исходящие webhook-и на события (новый лид, оплата, зачисление, абонемент)
  с подписью HMAC-SHA256 и повторами; ссылки на онлайн-занятия (Zoom по ключам, иначе Jitsi Meet) —
  кнопка «Войти в урок» у студента и ссылка в напоминании; оплата по ссылке (`/pay/<код>`) с автоматическим
  зачислением; фискальные чеки на каждую оплату. Ключи провайдеров — в `apps/api/.env` (см. `.env.example`).

## Запуск для разработки (Windows)

Нужны Node.js 22+ и PostgreSQL 17.

```powershell
npm install
copy apps\api\.env.example apps\api\.env   # заполнить DATABASE_URL, JWT_SECRET, WEBHOOK_TOKEN
npm run db:migrate                          # создать таблицы
npm run db:seed                             # демо-данные (учётные записи — в apps/api/prisma/seed.ts)
npm run dev:api                             # API: http://localhost:3000/api/v1, Swagger: /api/docs
npm run dev:web                             # Веб: http://localhost:5173
```

Мобильное приложение (Android / iOS, Expo) — отдельный пакет `apps/mobile`, см. [apps/mobile/README.md](apps/mobile/README.md):

```powershell
cd apps/mobile; npm install; npx expo start    # QR для Expo Go; --web — проверка в браузере
```

- Мобильное приложение (этап 4, итерация 1): студент и родитель — баланс и оплата долга, абонементы, расписание
  с входом в онлайн-урок, оценки и посещаемость, ДЗ, сообщения; преподаватель — журнал в 2 нажатия с отметками
  без интернета; push-уведомления через Expo Push Service (FCM / APNs). Переменная `EXPO_ACCESS_TOKEN` в `.env` API — необязательна.
